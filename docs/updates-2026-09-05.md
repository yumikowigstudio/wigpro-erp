# อัปเดตการเชื่อมโยง POS และการเงิน

## รายการที่แก้ในรอบนี้

1. บันทึกขาย สต๊อก ใบสั่งผลิต คอมมิชชั่น และการปิดมัดจำในธุรกรรมเดียวกัน ไม่ออกใบเสร็จสำเร็จหากบันทึกส่วนที่เกี่ยวข้องไม่ครบ
2. กันการส่งคำสั่งซ้ำ และตรวจสต๊อกล่าสุดขณะบันทึก ลดปัญหาสองเครื่องขายสินค้าชิ้นสุดท้ายพร้อมกัน
3. รับมัดจำหลายงวดพร้อมวันที่ วิธีชำระ ผู้รับเงิน และสถานะยืนยัน ยอดคงเหลือเชื่อมกับงานผลิต
4. เปิด POS จากใบมัดจำได้ ดึงสินค้า/บริการเดิมและหักยอดรับสะสมที่ยังใช้ได้ โดยไม่สร้างงานผลิตซ้ำ
5. คืนสินค้าโดยอิงราคาสุทธิของบิลเดิม รวมส่วนลดและ VAT ไม่บวก VAT ซ้ำ ตรวจจำนวนที่เคยคืนแล้ว
6. ยกเลิกบิลพร้อมคืนสต๊อกเฉพาะจำนวนที่ยังไม่เคยคืน บันทึกเหตุผลและผู้ยกเลิก เลือกคงหรือยกเลิกงานผลิตที่เกี่ยวข้อง
7. แยกยอดรอคืนออกจากการคืนเงินจริง มีปุ่มบันทึกยอด/วิธีคืนเงิน และกันคืนเงินเกินยอด
8. การโอนและตรวจรับสต๊อกบันทึกพร้อมรายการเคลื่อนไหว ตรวจรับซ้ำไม่เพิ่มสต๊อกซ้ำ
9. รายงานแยกสาขาและหน้าบัญชีใช้ประวัติเงินรับจริง ไม่รวมมัดจำซ้ำกับบิลปิดยอด และแสดงเงินคืนตามวันที่คืนจริง
10. แนบสลิปย้อนหลังไม่เปลี่ยนบิลที่ยืนยันชำระแล้วกลับเป็นรอตรวจสอบ และไม่ยืนยันชำระบิลที่ถูกยกเลิกแล้ว
11. เพิ่มค้นหาด้านบนตามต้นชื่อ เบอร์โทร รหัสสินค้า เลขบิล เลขมัดจำ และเลขงาน ตามสิทธิ์ผู้ใช้งาน
12. เพิ่มพักบิลและเรียกคืนตะกร้าที่ค้างไว้ แยกตามบัญชีและสาขาในเครื่องเดิม
13. ตัวเลขแจ้งเตือนอ้างอิงรายการจริง พร้อมสถานะอ่านในเครื่องเดิมและลิงก์เปิดรายการที่เกี่ยวข้อง
14. Activity Log เรียงล่าสุดจากฐานข้อมูล กรองวันที่ และโหลดเพิ่มเป็นหน้าได้
15. คงสาขาที่เจ้าของร้านเลือกไว้เมื่อเปลี่ยนหน้า ไม่ดึงกลับไปสาขาประจำระหว่างใช้งาน และโหลดรายชื่อสาขาร่วมกันชุดเดียวเพื่อลดการอัปเดตหน้าจอซ้ำ

## วิธีใช้

- **พักบิล:** ใน POS กด “พักบิล” แล้วเรียกกลับจาก “บิลที่พัก” ก่อนยืนยันให้ตรวจราคา สต๊อก และการรับเงินอีกครั้ง บิลที่พักไม่ใช่ยอดขายและยังไม่ตัดสต๊อก
- **กู้ตะกร้า:** หลังรีเฟรชหรือกลับมา POS กด “เรียกคืน” ที่ตะกร้าค้าง ไม่เก็บการยืนยันรับเงินอัตโนมัติ
- **รับเพิ่ม:** หน้า “มัดจำ” กด “รับชำระ” ดูทุกงวดที่ “ประวัติรับเงิน” รายการรอตรวจสอบต้องกดยืนยันรับเงินจริง
- **ปิดมัดจำ:** หน้า “มัดจำ” กด “เปิดบิลปิดมัดจำ” ตรวจรายการและยอดคงเหลือ แล้วชำระตามปกติ
- **ยกเลิก:** เปิดบิลใน “ประวัติบิล” หรือรายการมัดจำ กด “ยกเลิกรายการ” ใส่เหตุผลและเลือกจัดการงานผลิต
- **คืนเงินหลังยกเลิก:** กด “รอคืน...” บันทึกยอดและวิธีคืนเมื่อคืนเงินจริงแล้ว การยกเลิกเอกสารเพียงอย่างเดียวไม่ถือว่าคืนเงินจริง
- **รายงาน:** หน้า “รายงาน > แยกสาขา” เลือกช่วงวันที่ ดูยอดขายแยกจากรับเงินสุทธิ หน้า “บัญชี” แสดงเงินรับ/จ่ายจริงของสาขาที่เลือก ไม่ใช่การคำนวณกำไรทางบัญชีเต็มรูปแบบ
- **ตรวจย้อนหลัง:** หน้า “บันทึกกิจกรรม” เลือกวันที่แล้วโหลดเพิ่ม การค้นหาข้อความ/หมวดกรองภายในรายการที่โหลดมา

## ข้อมูลเดิมและขอบเขต

- ไม่ลบหรือเขียนทับข้อมูลลูกค้าเดิมเพื่อทดสอบ
- งวดชำระเดิมที่ไม่มีวันที่รับเงินจริงแสดงว่าไม่ทราบวันที่ และไม่เดานำยอดเข้าช่วงวันที่รายงาน
- บิลที่ยกเลิกก่อนมีระบบติดตามคืนเงินยังไม่มีหลักฐานยืนยันยอดคืนในระบบ ต้องตรวจจากเอกสารเดิม ไม่สร้างรายการคืนย้อนหลังอัตโนมัติ
- มัดจำเดิมที่ไม่ผูกสินค้า/บริการให้เลือกสินค้าด้วยตนเองใน POS และเลือกใบมัดจำ
- พักบิลและสถานะอ่านแจ้งเตือนเก็บในเบราว์เซอร์เครื่องเดิม ยังไม่ซิงก์ข้ามเครื่อง
- รอบนี้ยังไม่ใช่การแบ่งหน้าครบทุกหน้าของระบบ การรวมหน้าชิ้นงานทั้งหมด และระบบเปิด/ปิดกะเงินสดยังเป็นงานแยก

## การตรวจสอบ

- `npm test`: 7 กรณีคำนวณเงิน รวม VAT เก่าแบบผสม ส่วนลด การคืนบางชิ้น และวันรับเงิน
- `npm run test:emulator`: ทดสอบธุรกรรม 10 กรณีในโครงการจำลอง `demo-yumiko-qa` ไม่ใช้ฐานข้อมูลร้านจริง
- `tests/ui-smoke.mjs`: ทดสอบเบราว์เซอร์ด้วยบัญชีจำลองบนเดสก์ท็อปและมือถือ ภาพตรวจอยู่ใน `test-results/` ซึ่งไม่เข้า Git
- `npm run lint`, `npx tsc --noEmit`, `npm run build`
- Emulator ใช้ Java 21 และพอร์ต Firestore 8086 / Auth 9096 ชุดทดสอบเป็นผู้โหลดกฎก่อนสร้างข้อมูล
- UI smoke ต้องเปิด dev server พอร์ต 3106 โดยใช้โครงการ demo และ `NEXT_PUBLIC_FIREBASE_EMULATORS=true` เท่านั้น แล้วรันผ่าน `firebase emulators:exec`
